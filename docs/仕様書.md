# アプリ仕様書：ともだちのたね

## 1. アプリの名前と目的

- **アプリ名**：ともだちのたね
- **目的**：学校で新しい友達を作るきっかけを提供する中高生向けのプロフィール帳アプリ。高校入学やクラス替えなどの新しい環境において、名前・誕生日・趣味・好きな音楽・MBTIなどのプロフィール情報を交換・閲覧できるようにし、共通点や話題を見つけて自然なコミュニケーションや実際の会話へつなげることを目指す。

---

## 2. 画面一覧（画面名と表示内容）

| 画面名 | 表示内容 |
| --- | --- |
| **ログイン画面（登録画面）** | アプリの初期画面。「ログイン」「新規登録」の選択ボタンを表示。 |
| **新規登録画面** | メールアドレス・パスワード入力フォーム、「戻る」「新規登録」ボタンを表示。 |
| **プロフィール作成画面** | アカウント作成直後のプロフィール入力画面（名前、誕生日、星座、血液型、性別、好きな〇〇トップ3、趣味、ハマっていること、音楽、MBTI、将来の夢、自分の第一印象、プロフィール画像）。 |
| **ホーム画面** | 登録済みの自分のプロフィール情報（myプロフィール）を表示。上部に設定アイコン、下部に他画面へのナビゲーションボタンを表示。 |
| **友達追加画面** | 友達検索フォームと「おすすめ」の友達一覧を表示。各友達の横に「＋」ボタン、下部にナビゲーションボタンを表示。 |
| **友達のプロフィール観覧画面** | 友達（A、Bなど）のプロフィール情報カードを表示。カード切り替え（めくり機能）、いいね（ハート）アイコン、他人の第一印象欄を表示。 |
| **自分のプロフィール画面（編集画面）** | 自分のプロフィール情報を編集・保存する画面。画面右上に「保存」ボタン、下部にナビゲーションボタンを表示。 |

## 7. 守る条件

- **使用技術**：HTML・CSS・JavaScript のみで作成する（データベースおよびバックエンドログイン機能は作成しない）。
- **ファイル構成**：画面ごとに個別のHTMLファイルを作成し、最初の画面は `index.html` とする。
- **共通スタイル・スクリプト**：全画面で共通の `style.css` と `script.js` を読み込んで使用する。
- **ファイル名・パス**：ファイル名はすべて半角英数字（小文字・アンダースコア推奨）とし、CSS/JSおよびページ間遷移の読み込みは相対パス（`./`から始める）で指定する。
- **機能・画面範囲**：添付の図に描かれている画面・ボタンのみを実装し、図にない機能や画面は追加しない。
- **レスポンシブデザイン**：スマートフォン画面サイズ（幅375px〜430px基準）で見やすいレイアウトとし、白・黒・灰色を基本色とした仮のデザインで構成する。
- **ボタン表記**：ワイヤーフレーム上の（ ）表記は注記のため画面上には出力しない（例：「確定する」）。
- **仮データ管理**：名前や地名は「利用者A」「サンプル町1-1」などの架空のデータを使用する。
- **画像配置**：画像は `./images/` フォルダ配下に置き、未準備の箇所は灰色の四角形プレースホルダーで表示する。

## 8. 確認したいこと（図にない・決まっていないこと）

1. **設定アイコン（歯車マーク）の機能と遷移先**
   - 「ホーム画面」および「友達のプロフィール観覧画面」に設定用歯車アイコンがありますが、クリック時の遷移先や動作が図に記載されていないため確認が必要です。
2. **友達追加画面の「＋」ボタンおよび「検索」バーの動作**
   - 友達追加画面における各ユーザー横の「＋」ボタンを押した際の動作（追加完了表示など）および検索入力の動作についての指定がありません。
3. **友達のプロフィール観覧画面における「ページめくり」演出**
   - ワイヤーフレーム上の「めくるとAからBにいける」動作について、左右スワイプまたは次へボタン等のどちらの操作インターフェースで実装するか確認が必要です。
4. **「いいね機能（ハートマーク）」の動作**
   - 友達のプロフィール上にあるハートマークを押した際の視覚的変化（色の切り替え）以外の連動動作（いいね数の加算や通知など）があるか確認が必要です。
5. **友人による書き込み項目（第一印象）の入力権限**
   - 友達のプロフィール画面にある「ex)自分の第一印象」について、観覧者がその場で直接書き込み・送信できるか確認が必要です。
